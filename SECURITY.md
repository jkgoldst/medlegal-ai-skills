# Security and safety reports

## What to report privately

- A way a skill can be made to leak, alter, or invent case information.
- A skill that gives unsafe guidance, such as telling a physician a report is ready to sign.
- Real patient or case information that has been posted anywhere in this repository, its issues, or its pull requests.
- A security problem with the website or the downloads.

## How to report

Use GitHub's private reporting: open the **Security** tab of this repository and choose **Report a vulnerability**. Only the maintainers can see the report.

Do not open a public issue for any of the items above.

**Never include real patient or case information in a report.** Describe the problem with invented data. If you found real information that someone else posted, tell us where it is. Do not copy it.

## What to expect

This is a small project. We read every report and reply when we can. A confirmed problem with a skill becomes a new test case before the skill changes.

## What a skill does not protect against

The skills are written instructions. They are not security controls.

- A skill tells the AI to ignore instructions hidden in case documents. That lowers the risk. It does not remove it.
- A skill provides no HIPAA compliance. Where your documents go is decided by the AI tool you run it in.
